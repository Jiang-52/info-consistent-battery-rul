【总回复】
导师指出的核心问题是：cycle_norm=t/T 把目标完整寿命 T 写入输入，而标签
RUL=T-t，不能再当作普通 ML 特征。本稿已据此改定位为「评价方法学 / benchmark
protocol」论文，建立 L0/L1/L1P/L2 信息层级与 Protocol A/B 双轴，并以 Severson
Protocol B（n=24）为主证据。不再做新架构或模型动物园。

一、修改清单（按导师意见条目）
--------------------------------------------------------------------------------

【意见1】t/T 含目标寿命信息，存在信息泄露，不能当普通特征
【修改】
  - Abstract/Intro 明确写出：标签 RUL_t=T-t，故 t/T 使 T 同时进入 X_t 与 Y；
    在预测时不可得 T 的在线设定下，该通道为 retrospective oracle，非 online-valid。
  - 形式约束：T∈Y，T∉X_t（除具名 L2 oracle）；X_t⊆O_t。
  - Related Work 将 “leakage” 限定为 use-case 下不合法目标信息；正文主术语改为
    retrospective oracle / online information-inconsistent。
【回复】已按导师意见彻底改正前提：不再把 t/T 包装为普通特征，而定义为有意命名的
  回顾性 oracle（L2），并与在线合法主张分开报告。

【意见2】T/EOL 定义不当（用记录末循环抹平寿命差异）
【修改】
  - 统一 T:=首次 SOH≤0.7 的循环（first-EOL），不用 T_record 作为主定义。
  - Table（寿命表）给出 NASA/CALCE 的 T_record vs T_EOL 与 regeneration。
  - 原 T_record 下的结果保留为 Legacy 历史基线，标明非主证据。
【回复】已修正寿命定义；并用表格证明 record length 会掩盖异质寿命，这是协议问题
  而非单纯删特征。

【意见3】不能只说“有泄露”，要建立系统评价框架
【修改】
  - 建立信息层级：L0（raw t）→ L1（t/T_prior）→ L2（t/T_target），另设非仿射
    诊断 L1P（SOH 匹配同胞 RUL）。
  - 正文声明：嵌套对象是「允许的寿命常数」，不是严格信息滤子（避免过度数学化）。
  - 标题已去掉 “Nested”，改为 Information-Level Framework（降低攻击面）。
  - 贡献定为报告标准 / 评价协议，非新 RUL 架构。
【回复】已从个案 leakage 升为可操作的信息层级 + 报告模板；框架贡献与实验主线对齐。

【意见4】信息层级与拟合协议不可混为一谈；需 leave-target 主实验
【修改】
  - 明确双轴：Information level I_t 与 Fit protocol（A/B）分开；禁止未命名并表排名。
  - Protocol A：同电芯时序 early 80% 支撑 / late 20% 测试；支撑集内末 15% 验证、
    85% 训练；scaler 仅训练集；早停看 val RUL RMSE；注明滑动窗重叠。
  - Protocol B：严格 leave-target-cell-out；同胞池种子置换后末 15% 验证。
  - 主证据：Severson Protocol B，n=24，中位 RMSE 222.1→33.5→30.3→12.0，
    L0>L2 全细胞，Wilcoxon p=1.2×10^{-7}。
  - Results 叙事已改为 Severson 主证据在前，NASA/CALCE/Legacy 为探索/历史。
【回复】已补齐「同电芯回顾」与「留出目标」两条协议，并以异质寿命 leave-target
  结果作为主支撑，回应“只有泄漏说法、实验不足”的批评。

【意见5】实验是否只做一个模型 / 是否堆模型
【修改】
  - MLP 与 Patch-TF 仅作匹配预算下的 ranking instruments，不作 SOTA / 新骨干声明。
  - 不引入 LSTM/GRU/CNN/PINN/UQ 主线；MC-Dropout 附录化且不作校准宣称。
  - 具名 L0 基线：persist_fade / persist_recursive / persist_hold（标明 oracle）。
【回复】实验服务于信息层级对比，而非模型比拼；刻意避免模型动物园。

【意见6】L1≈L2 可能只是尺度问题，不能直接当“语义信息”结论
【修改】
  - 写明 L1/L2 在输入层面对 t 仿射重标度；近等预测报告为经验尺度稳健性，
    非模型不变性定理。
  - Priority-1 scale-control：L1 vs L2 点态差、相关>0.97、raw t、t/1000、
    Protocol A 外推比例；并标明 scale-control 为独立重跑，不与主表混用 s.d.。
【回复】已主动承认尺度混淆并给出对照；结论改为「部分归因于数值尺度」。

【意见7】L1P 是否人造 / 是否总能更好
【修改】
  - 正式定义 SOH 匹配 L1P；报告匹配距离（NASA 很小）。
  - Finding：NASA 上 L1P 可优于 L2（如 B0005：5.06 vs 23.58）；CALCE CS2_36
    则 L1P≫L2（60.69 vs 2.20）——证明「更多目标寿命信息 ≠ 必然更低 RMSE」。
【回复】L1P 用作诊断通道，不作默认在线估计器；反例避免“信息越多越好”的简化故事。

【意见8】SOH / UQ 喧宾夺主
【修改】
  - SOH 为辅助对照；双头 SOH 恶化明确为多任务干扰，不作 SOH 部署基准。
  - UQ（MC-Dropout）附录-only，撤回校准宣称。
【回复】已降级，主线回到 RUL 信息层级评价。

【意见9】Protocol A 的 train/validation 切分表述不清（后续封口意见）
【修改】
  - Methods §Fit protocols 补全：时序 80/20；支撑集内时序末 15% 为 val；
    scaler/参数估计不用 val/test；早停定义；滑动窗重叠 caveat。
  - Protocol B 的 15% val（种子置换）一并写清。
【回复】已按代码实际实现写死切分，消除“early 80% 含糊 train/val”的攻击点。

【意见10】数字与表格需与代码一致（防错位）
【修改】
  - 对照 outputs：寿命表 regen/EOL；Severson 中位与 p 值；主表 L1P 与 Abstract
    数字已核对（以 generated_tables / severson_loco/summary 为准）。
  - OLS 恒等式检查整表移入附录，正文仅一句。
【回复】关键数字已做 checksum；投稿前仍建议终校一次 PDF 与表号。
